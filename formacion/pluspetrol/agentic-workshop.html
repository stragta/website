IA agéntica.
Un sistema gerencial.

Construye en una carpeta local con ChatGPT Work o Codex un sistema gerencial que investiga noticias, organiza documentos y consolida el trabajo en un dashboard. Esta guía reúne la arquitectura y los prompts listos para copiar y pegar.

Qué vas a construir. Un sistema agéntico dentro de un proyecto local con ChatGPT Work o Codex. El perfil cambia por persona; la arquitectura permanece. Las entradas nacen de la búsqueda real y la selección; el dashboard separa resultados, candidatos y referencias pendientes.
01
Arquitectura

El sistema en una mirada

El Coordinador recibe el objetivo, detecta qué cambió y delega el trabajo especializado. No necesitas tres productos diferentes: los tres agentes viven en el mismo proyecto y comparten una estructura de carpetas y contratos de salida.

PerfilIntereses, cargo y temas
EntradasNoticias y documentos
AgentesInvestigar y catalogar
CoordinaciónValidar y consolidar
DashboardEstado y pendientes
Investigador

Busca noticias reales, verifica fuentes y detecta documentos relacionados.

Bibliotecario

Recupera documentos seleccionados, cataloga archivos y registra referencias pendientes.

Coordinador

Asigna, valida, registra la actividad y actualiza el dashboard.

La definición operativa: la IA recibe un objetivo, organiza pasos, utiliza herramientas, delega tareas, verifica resultados y deja un estado visible.

05
Especialización

Tres responsabilidades coordinadas

Investigador

Busca noticias, verifica fuentes, evalúa relevancia y detecta documentos relacionados.

Bibliotecario

Recupera y cataloga los documentos aprobados; organiza archivos, fuentes, versiones y referencias.

Coordinador

Dirige la investigación, asigna tareas, recoge resultados, valida y actualiza el dashboard.

Define los contratos del Investigador, Bibliotecario y Coordinador y la configuración de investigación en el paso 06 de construcción desde cero. La base limpia ya incluye esos contratos. La delegación real o la ejecución por roles se registra según las herramientas disponibles.

06
Investigación en vivo

Investiga con revisión humana

Perfil → plan → búsqueda → selección → análisis y catalogación → consolidación → dashboard.

Completa los prompts del paso 09 desde cero o del paso 06 de la base preparada. El plan se aprueba antes de buscar y los candidatos se seleccionan antes de consolidar.

Inicia una investigación para el perfil de config/perfil.json.

Actúa como Coordinador y encarga al Investigador un plan.

Propón:
- consultas de búsqueda;
- temas prioritarios;
- fuentes;
- ventana temporal de siete días para noticias;
- hasta cinco noticias;
- hasta tres documentos oficiales relacionados.

Los documentos de referencia pueden ser anteriores a la ventana
de noticias. Prioriza su vigencia y explica su relación con el tema.

Confirma las herramientas web disponibles.
No busques todavía. Muéstrame el plan y espera aprobación.
07
Verificación

Prueba y corrige

La prueba no consiste en comprobar solamente si aparece texto. Hay que verificar si el sistema conserva fuentes, reconoce archivos repetidos y detiene el proceso cuando falta información.

Audita la última ejecución sin modificar archivos.

Comprueba:
1. que cada noticia conserva su fuente y fecha de consulta;
2. que cada documento local conserva ruta y huella, y cada referencia URL conserva su estado de acceso;
3. que no existen duplicados por id, URL o archivo;
4. que las inferencias están separadas de la evidencia;
5. que las advertencias llegaron al dashboard;
6. que una ejecución sin cambios no duplica registros;
7. que las horas aparecen como declaradas o estimadas, nunca como medidas si no existe un registro de tiempo.

Devuélveme una lista de hallazgos y su nivel de prioridad.
  • El perfil corresponde a la persona que ejecuta.
  • El investigador responde solo al campo de interés.
  • El bibliotecario puede volver a localizar cada archivo.
  • El Coordinador no inventa datos faltantes.
  • El dashboard conserva el historial.
  • Los bloqueos requieren intervención humana.
08
Continuidad

De la ejecución manual a la programada

Una programación no reemplaza al Coordinador: solo inicia una nueva ejecución. Primero prueba el flujo manual; después guarda una tarea con el mismo objetivo y una frecuencia definida.

Programa una actualización diaria a las 07:30, hora de America/Guayaquil.

En cada ejecución:
- revisa las noticias nuevas según mi perfil;
- procesa únicamente documentos nuevos o modificados;
- delega el trabajo al Investigador y al Bibliotecario;
- consolida el resultado en el dashboard;
- informa solo cambios materiales, advertencias o decisiones pendientes.

No publiques, envíes mensajes ni modifiques las fuentes de entrada.
Confirma la frecuencia, el proyecto y el destino antes de guardar la programación.

Condición práctica: las tareas programadas con archivos locales dependen de que la función esté disponible en la cuenta y de que el computador y la aplicación permanezcan disponibles cuando el proyecto local deba ejecutarse.

Mensaje de cierre para la herramienta local

Prepara este proyecto para entregarlo a otra persona.

Comprueba que:
- no contenga datos institucionales ni secretos;
- config/perfil.json conserve campos editables;
- las carpetas de entrada estén vacías;
- los datos del dashboard estén limpios;
- AGENTS.md y README.md expliquen el flujo;
- la ejecución manual funcione desde una instalación limpia.

No cambies la arquitectura ni publiques el proyecto.

El principio de reutilización: cada participante cambia el perfil y sus fuentes; la arquitectura de Investigador, Bibliotecario y Coordinador permanece.

04
Personalización

Configura tu perfil

Cada persona conserva la misma arquitectura y completa un objeto JSON con los campos que espera el validador.

Ayúdame a completar config/perfil.json.

Pregúntame una cosa a la vez:
1. nombre;
2. cargo;
3. organización;
4. campo de interés;
5. temas de noticias que debo vigilar;
6. categorías de documentos que manejo, como informes técnicos,
   normativa, estadísticas sectoriales o estudios de mercado;
7. zona horaria;
8. idioma.

Debes utilizar exactamente esta estructura:

{
  "nombre": "",
  "cargo": "",
  "organizacion": "",
  "campo_interes": "",
  "temas_noticias": [],
  "tipos_documentos": [],
  "zona_horaria": "America/Guayaquil",
  "idioma": "es"
}

No cambies los nombres de las propiedades.
El archivo debe contener un objeto JSON, no una lista.

“tipos_documentos” se refiere a categorías documentales, no a
extensiones o formatos de archivo.

Antes de guardar, muéstrame la propuesta completa.
Cuando la confirme, modifica únicamente config/perfil.json.
No inventes ningún dato.
