IA agéntica.
Un sistema gerencial.

Construye dentro de Codex un sistema gerencial que investiga noticias, organiza documentos y consolida el trabajo en un dashboard. Esta guía reúne la arquitectura y los prompts listos para copiar y pegar.

Qué vas a construir. Un sistema agéntico dentro de un proyecto de Codex. El perfil cambia por persona; la arquitectura permanece. Las noticias, los documentos y el dashboard son entradas y resultados separados para que el trabajo sea trazable.
01
Arquitectura

El sistema en una mirada

El Coordinador recibe el objetivo, detecta qué cambió y delega el trabajo especializado. No necesitas tres productos diferentes: los tres agentes viven en el mismo proyecto y comparten una estructura de carpetas y contratos de salida.

PerfilIntereses, cargo y temas
EntradasNoticias y documentos
AgentesInvestigar y catalogar
CoordinaciónValidar y consolidar
DashboardEstado y pendientes
Investigador

Busca, contrasta y resume las noticias que importan para el perfil.

Bibliotecario

Lee la carpeta documental, clasifica archivos y crea fichas localizables.

Coordinador

Asigna, valida, registra la actividad y actualiza el dashboard.

La definición operativa: la IA recibe un objetivo, organiza pasos, utiliza herramientas, delega tareas, verifica resultados y deja un estado visible.

05
Especialización

Construye los tres agentes

Los contratos .md contienen el papel, las entradas, los límites y el formato de salida de cada agente. El modelo puede cambiar; el contrato mantiene el comportamiento esperado.

5.1 · Agente Investigador

Su carpeta de entrada es entrada/noticias. Su salida es un conjunto de registros verificables en resultados/pendientes/investigador.json.

Construye el Agente Investigador dentro de este proyecto.

Lee config/perfil.json y agentes/investigador.md.
Revisa únicamente las fuentes que el Coordinador enumere en estado/ejecucion_actual.json.
Para cada noticia:
- conserva título, fuente, enlace y fechas;
- resume sin inventar información;
- clasifica la relevancia para este perfil;
- separa evidencia de inferencia;
- registra cualquier dato faltante como advertencia.

Escribe el resultado en resultados/pendientes/investigador.json.
No modifiques las fuentes de entrada ni el perfil.

5.2 · Agente Bibliotecario

Su carpeta de entrada es entrada/documentos. Su salida es una biblioteca actualizable en resultados/pendientes/bibliotecario.json.

Construye el Agente Bibliotecario dentro de este proyecto.

Lee config/perfil.json y agentes/bibliotecario.md.
Revisa únicamente los documentos que el Coordinador enumere en estado/ejecucion_actual.json.
Para cada archivo:
- identifica título, tipo, fecha y autor o institución cuando existan;
- crea un resumen breve y localizable;
- asigna temas y palabras clave;
- conserva la ruta y la huella del archivo;
- separa evidencia de inferencia;
- registra cualquier dato faltante como advertencia.

Escribe el resultado en resultados/pendientes/bibliotecario.json.
No modifiques los documentos de entrada.

5.3 · Agente Coordinador y dashboard

Es el agente que ve el proyecto completo. Organiza el trabajo y solo consolida resultados que respeten los contratos.

Construye el Agente Coordinador siguiendo agentes/coordinador.md.

En cada ejecución:
1. lee el perfil y la configuración;
2. ejecuta el plan para detectar entradas nuevas o modificadas;
3. delega noticias al Investigador;
4. delega documentos al Bibliotecario;
5. espera ambos resultados;
6. valida sus contratos JSON;
7. consolida radar, biblioteca y actividad;
8. actualiza dashboard/data.json;
9. informa cambios, advertencias y decisiones pendientes.

Si un agente queda parcial o bloqueado, no marques sus archivos como procesados.
No publiques ni envíes nada fuera del proyecto sin aprobación humana.
06
Primera corrida

Ejecuta el sistema manualmente

La primera corrida debe ser manual. Así podemos observar qué decide el Coordinador, qué recibe cada especialista y qué termina en el dashboard.

Inicia una ejecución manual del sistema agéntico.

1. Valida mi perfil.
2. Detecta noticias y documentos nuevos o modificados.
3. Prepara el plan y muéstrame las tareas.
4. Delega cada tarea al agente correspondiente.
5. Espera los resultados.
6. Valida los JSON de salida.
7. Consolida el dashboard.

Al terminar, responde con:
- noticias nuevas procesadas;
- documentos nuevos procesados;
- cambios del dashboard;
- advertencias;
- decisiones que requieren mi aprobación.
Entrada

Nuevos archivos en las carpetas asignadas.

Proceso

Delegación, lectura, clasificación y validación.

Salida

Datos consolidados, historial y pendientes.

07
Verificación

Prueba y corrige

La prueba no consiste en comprobar solamente si aparece texto. Hay que verificar si el sistema conserva fuentes, reconoce archivos repetidos y detiene el proceso cuando falta información.

Audita la última ejecución sin modificar archivos.

Comprueba:
1. que cada noticia conserva su fuente y fecha de consulta;
2. que cada documento conserva su ruta y huella;
3. que no existen duplicados por id, URL o archivo;
4. que las inferencias están separadas de la evidencia;
5. que las advertencias llegaron al dashboard;
6. que una ejecución sin cambios no duplica registros;
7. que las horas aparecen como declaradas o estimadas, nunca como medidas si no existe un registro de tiempo.

Devuélveme una lista de hallazgos y su nivel de prioridad.
  • El perfil corresponde a la persona que ejecuta.
  • El investigador responde solo al campo de interés.
  • El bibliotecario puede volver a localizar cada archivo.
  • El Coordinador no inventa datos faltantes.
  • El dashboard conserva el historial.
  • Los bloqueos requieren intervención humana.
08
Continuidad

De la ejecución manual a la programada

Una programación no reemplaza al Coordinador: solo inicia una nueva ejecución. Primero prueba el flujo manual; después guarda una tarea con el mismo objetivo y una frecuencia definida.

Programa una actualización diaria a las 07:30, hora de America/Guayaquil.

En cada ejecución:
- revisa las noticias nuevas según mi perfil;
- procesa únicamente documentos nuevos o modificados;
- delega el trabajo al Investigador y al Bibliotecario;
- consolida el resultado en el dashboard;
- informa solo cambios materiales, advertencias o decisiones pendientes.

No publiques, envíes mensajes ni modifiques las fuentes de entrada.
Confirma la frecuencia, el proyecto y el destino antes de guardar la programación.

Condición práctica: las tareas programadas con archivos locales dependen de que la función esté disponible en la cuenta y de que el computador y la aplicación permanezcan disponibles cuando el proyecto local deba ejecutarse.

09
Entrega

Descarga y reutiliza

La base limpia contiene la estructura, los contratos de los agentes, el código de coordinación y los archivos JSON vacíos. No contiene todavía noticias ni documentos sintéticos.

Descargar la versión base · v0.1

Después del taller se preparará una versión final con prompts didácticos, datos sintéticos, dashboard web y un nuevo número de versión.

Mensaje de cierre para Codex

Prepara este proyecto para entregarlo a otra persona.

Comprueba que:
- no contenga datos institucionales ni secretos;
- config/perfil.json conserve campos editables;
- las carpetas de entrada estén vacías;
- los datos del dashboard estén limpios;
- AGENTS.md y README.md expliquen el flujo;
- la ejecución manual funcione desde una instalación limpia.

No cambies la arquitectura ni publiques el proyecto.

El principio de reutilización: cada participante cambia el perfil y sus fuentes; la arquitectura de Investigador, Bibliotecario y Coordinador permanece.

04
Personalización

Configura tu perfil

El perfil es la parte que cambia entre participantes. La arquitectura permanece igual.

Ayúdame a configurar el perfil del sistema.

Pregúntame, una pregunta a la vez:
1. nombre;
2. cargo;
3. organización;
4. campo de interés;
5. temas de noticias que debo vigilar;
6. tipos de documentos que manejo;
7. zona horaria.

Después muéstrame una propuesta y, cuando la confirme, actualiza únicamente config/perfil.json.
No inventes ningún dato y conserva la estructura JSON.
